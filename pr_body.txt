🚮 Smell: The `check_locals` function in `crates/duke-bytecode/src/verifier.rs` contained a massive, 75-line inline `match` block to determine which local variable index an instruction was accessing. This violated the principle of extracting large logic blocks into helpers and buried instruction-specific data mapping inside verification logic.
✨ Solution: Extracted the local variable mapping logic into a new `pub const fn local_variable_index(&self) -> Option<usize>` method directly on the `Instruction` enum in `crates/duke-bytecode/src/instruction.rs`. The `check_locals` function now simply calls this method. Added comprehensive unit tests for the new method.
🧼 Benefit: Significantly flattens the `check_locals` function, cleanly encapsulates instruction-specific data mapping on the `Instruction` type itself, and drastically improves readability.
🛡️ Verification: Tests passed. No logic changed. Added tests for `local_variable_index`.
