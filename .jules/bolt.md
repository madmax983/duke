**Eliminating intermediate Vec allocations with pre-sized loops**
**Learning:** `set_string_layout` initialized Java Strings by first generating an intermediate `Vec<u8>` via `.collect()` and then iterating over it to write to the `HeapObject`'s `fields` slice. This created an unnecessary `O(N)` heap allocation for every string.
**Action:** Always look for opportunities to compute the final size (`value.chars().count()` or `encode_utf16().count() * 2`) upfront, allocate the target buffer (e.g. `allocate("[B")`), and write values directly into it using a loop instead of relying on `.collect()`.
