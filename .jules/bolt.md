**E0502: Overlapping Mutability in GC Heap**
**Learning:** When attempting to eliminate `.clone()` allocations by exposing lightweight slice references (`&str` and `&[Slot]`) from a central `Heap`, you cannot pass those references into any function that also mutably borrows the `Heap` (such as `ops.invoke(&mut heap, class_name)`). Rust's NLL will reject this with `E0502` because the immutable slice still borrows `Heap`.
**Action:** Before optimizing `.clone()` calls, trace the lifecycle of the borrowed data. If the borrow extends across a mutable operation, either scope the borrow tightly inside a block `{ ... }` to drop it early, or accept the allocation if the API signature enforces overlapping access.
