- 2026-07-10: The `gson-2.11.0` `toJson`/`fromJson` canary (`oss_jar_smoke::gson_smoke_runs_real_jar_bytecode`) is now GREEN end-to-end: it runs unmodified `gson` bytecode to serialize `new Pojo(7, "duke")` and deserialize it back, printing `gson round-trip: {"count":7,"name":"duke"} -> count=7 name=duke`. The load-bearing root cause was a GC bug where nested `<clinit>` execution states were not registered as GC roots, so a collection during a nested class initializer freed live objects and left stale roots; fixed separately in PR #1318 / branch `swarm/gc-nested-clinit-roots` ("register all active nested execution states as GC roots"). On top of that fix, a 21-blocker capability chain was cleared in execution order: the `java/lang/reflect/Type` marker interface, the `Class` reflection natives (`getModifiers`, `isInterface`, `isPrimitive`, `isRecord`, `isAnonymousClass`, `getGenericSuperclass`, `isAssignableFrom`, `cast`), `Field.getModifiers`/`getGenericType`/`getType`/`get`, reflective `sun/misc/Unsafe.allocateInstance` for `fromJson` (gson's `ConstructorConstructor` fallback for `Pojo`), boxing all numerics (`Long`/`Short`/`Byte`/`Double`/`Float`, mirroring `Integer`) to extend `java/lang/Number` so `instanceof`/`checkcast Number` is correct, plus assorted `String`/`StringBuffer`/`Map` natives. KNOWN LIMITATIONS still open (tracked as `TODO(known-limitation)` in `native/reflect.rs`): `Class.getModifiers`/`isInterface` report ACC_PUBLIC-only (the real `ClassAccessFlags` are not carried on `ReflectedClassInfo`), and `Field.getModifiers` omits the transient/final bits (dropped when the Field mirror is built) — surfacing either needs plumbing through `registry.rs`. Additionally `sun/misc/Unsafe` and the synthetic `ThreadLocal` are not on the `KEEP_SYNTHETIC` allowlist, so an eventual `real_jdk_shadow` run would shadow them with real JDK bytecode that Duke does not yet fully support.
